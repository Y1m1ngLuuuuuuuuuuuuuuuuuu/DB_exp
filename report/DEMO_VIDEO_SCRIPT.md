# 学生选课成绩管理系统视频展示脚本

## 1. 展示目标

视频建议控制在 8 到 12 分钟。展示重点不是单纯浏览页面，而是说明系统如何体现数据库原理2课程内容：

- ER 模型与实体联系；
- 关系模型与多对多转换；
- 规范化设计与 1NF、2NF、3NF、BCNF；
- 主键、外键、UNIQUE、CHECK 与触发器；
- 事务、行级锁与并发选课一致性；
- 视图、索引与查询优化；
- 成绩审计与运行维护。

## 2. 展示前准备

1. 启动 openGauss 容器并初始化数据库。
2. 确认 `migrate_triggers_constraints_20260608.sql`、`migrate_grade_policy_20260611.sql` 已执行。
3. 确认 `test_triggers_constraints.sql`、`test_grade_policy.sql` 和 `scripts/concurrency_enrollment_test.py` 的测试结果可展示。
4. 启动 Streamlit：
   ```bash
   .venv/bin/streamlit run app.py --server.port 8501 --server.address 127.0.0.1
   ```
5. 准备学生、教师、管理员演示账号。视频中只展示账号规则，不展示明文密码文件。
6. 准备最终 PDF：`report/main.pdf`。

演示数据覆盖 4 个学院、100 名学生、30 名教师和 50 门课程，因此课程列表、成绩记录和审计日志具有较好的展示效果。推荐演示账号为管理员 `A001`、教师 `T005` / `T021`、学生 `20240004` / `20240008` / `20240012`。边界选课案例建议使用学生 `20240009`、`20240010`、`20240011`。明文密码仅保存在本地 `secrets/DEMO_ACCOUNT_CREDENTIALS.md`，录制视频时不要展示该文件内容。

边界测试账号对应关系如下：

| 账号 | 演示场景 | 课程 / 教学班 | 预期结果 |
| --- | --- | --- | --- |
| `20240011` | 仅剩一名、先修课未满足、已满课程 | `EDGE_ONE_LEFT` / `9002`；`EDGE_ADV` / `9007`；`EDGE_FULL` / `9001` | 仅剩一名课程成功；先修课和已满课程失败 |
| `20240009` | 时间冲突、已满课程 | 已选 `EDGE_CONFLICT_A` / `9003`，再选 `EDGE_CONFLICT_B` / `9004`；`EDGE_FULL` / `9001` | 时间冲突失败；已满课程失败 |
| `20240010` | 同课跨班限制 | 已选 `EDGE_SAME` / `9005`，再选 `EDGE_SAME` / `9006` | 同一学期同一课程跨班重复选择失败 |

## 4. 操作脚本详细版

### 步骤 1：开场介绍

- 页面：无需登录，可先展示报告封面或登录页。
- 讲解：
  “本项目是基于 openGauss 的学生选课成绩管理系统。展示重点是数据库设计，包括 ER 模型、关系模型、规范化、完整性约束、触发器、事务和锁。”

### 步骤 2：登录页与角色体系

- 页面：登录页。
- 操作：
  1. 展示系统名称。
  2. 指出学生使用学号登录，教师使用教师编号登录，管理员使用管理员编号登录。
  3. 不展示明文密码。
- 讲解：
  “系统使用 `user_account` 保存认证信息，学生、教师、管理员档案分别保存在 `student`、`teacher`、`admin_profile` 中。角色档案一致性由数据库触发器检查。”

### 步骤 3：管理员首页

- 登录账号：管理员 `A001`。
- 页面：管理员首页。
- 操作：
  1. 展示学生数、教师数、开放课程、教学班、当前选课和成绩日志。
  2. 展示班次容量统计。
- 讲解：
  “管理员首页展示的是多个基础表和视图的汇总结果，反映系统的数据规模和运行状态。”

### 步骤 4：课程与教学班管理

- 页面：课程维护、开课安排。
- 操作：
  1. 展示课程定义。
  2. 展示某课程在某学期由某教师、某教室开设的教学班。
  3. 展示容量和上课时间。
- 讲解：
  “`course` 保存课程定义，`course_offering` 保存具体教学班，`course_schedule` 保存结构化上课时间片。这种分离减少了课程名称、教师信息、学期信息和教室容量的重复存储。”

### 步骤 5：学生正常选课

- 登录账号：学生 `20240004`，也可切换到 `20240008` 或 `20240012` 展示不同课表和成绩。
- 页面：课程查询与选课。
- 操作：
  1. 选择开放学期。
  2. 搜索一门有余量且不冲突的课程。
  3. 点击选课。
  4. 查看成功提示。
  5. 切换到课表或学生首页确认课程出现。
- 讲解：
  “学生与教学班之间是多对多关系，系统通过 `enrollment` 表保存选课记录。数据库层通过 `UNIQUE(student_id, offering_id)` 防止重复选择同一教学班，同时通过触发器检查容量、时间冲突、先修课程和同课跨班限制。”

### 步骤 6：选课边界案例

- 页面：课程查询与选课。
- 建议展示 2 到 3 个案例，避免视频过长。
- 推荐操作顺序：
  1. 登录 `20240011`，搜索 `EDGE_ONE_LEFT`，选择教学班 `9002`。预期成功，说明仅剩 1 个名额时，数据库在事务中锁定教学班并重新统计容量。
  2. 继续使用 `20240011`，搜索 `EDGE_ADV`，选择教学班 `9007`。预期失败，说明触发器会检查 `EDGE_PRE` 先修课是否已经 completed 且成绩达到 60 分。
  3. 登录 `20240009`，搜索 `EDGE_CONFLICT_B`，选择教学班 `9004`。预期失败，因为该学生已选 `EDGE_CONFLICT_A` / `9003`，两个教学班均为周六 1--2 节。
  4. 登录 `20240010`，搜索 `EDGE_SAME`，选择教学班 `9006`。预期失败，因为该学生已经选择同一课程的教学班 `9005`。
  5. 如需展示容量已满，登录 `20240009` 或 `20240011`，搜索 `EDGE_FULL`，选择教学班 `9001`。预期失败，因为该教学班容量 8 已满。
- 讲解：
  “这些结果不是单靠前端判断，而是由数据库函数、唯一约束和触发器兜底。`EDGE_FULL` 展示容量检查，`EDGE_CONFLICT_B` 展示结构化时间片支持时间冲突检查，`EDGE_SAME` 展示同课跨班规则，`EDGE_ADV` 展示先修课规则。即使绕过页面直接写数据库，也会被数据库拒绝。”

### 步骤 7：学生课表与成绩

- 页面：学生课表、成绩与绩点。
- 操作：
  1. 展示课表中的星期、节次、课程、教师、教室。
  2. 展示成绩、学分、状态和绩点。
- 讲解：
  “课表由 `v_student_timetable` 视图支撑。绩点不保存在 `enrollment.gpa_point` 基础字段中，而是通过 `grade_policy`、`grade_scale` 和绩点视图计算，避免派生字段与最终成绩不一致。”

### 步骤 8：教师成绩录入

- 登录账号：教师 `T005` 或 `T021`。
- 页面：教师首页、成绩管理。
- 操作：
  1. 选择一个教学班。
  2. 展示学生名单。
  3. 修改一个学生成绩。
  4. 勾选确认并保存。
- 讲解：
  “成绩更新由服务层事务执行，并在同一事务中设置当前操作者和修改原因。`trg_score_change_log` 在成绩变化后自动写入 `score_change_log`，保证成绩和审计日志原子一致。”

### 步骤 9：管理员成绩审计日志

- 登录账号：管理员演示账号。
- 页面：审计日志。
- 操作：
  1. 按课程、学生或教师筛选日志。
  2. 展示旧成绩、新成绩、修改人、修改时间和原因。
- 讲解：
  “成绩日志用于运行维护和责任追踪。它不是普通冗余字段，而是独立的审计事件记录。”

### 步骤 10：并发选课测试

- 页面：终端或报告附录。
- 操作：
  1. 展示 `scripts/concurrency_enrollment_test.py`。
  2. 展示测试输出：
     ```text
     success_count = 1
     failed_count = 1
     selected_count_in_db = 1
     ```
- 讲解：
  “两个独立连接同时抢容量为 1 的教学班，最终只有一个成功。`SELECT ... FOR UPDATE` 锁定 `course_offering` 行，使同一教学班的容量检查串行化。”

### 步骤 11：报告与 ER 图

- 页面：`report/main.pdf`。
- 操作：
  1. 展示概念 ER 图。
  2. 展示关系模式表。
  3. 展示范式审计表。
  4. 展示触发器清单和事务流程表。
- 讲解：
  “报告按数据库设计流程组织，每章都对应数据库原理2课程知识点。”

### 步骤 12：总结

- 页面：报告总结页或管理员首页。
- 讲解：
  “系统体现了数据库设计流程、ER 建模、关系模型、规范化、完整性约束、触发器、事务和锁。后续可以继续完善生产级权限、备份恢复、运行监控、教师评价和更大规模并发压测。”

## 5. 不建议展示的内容

1. 不展示明文密码。
2. 不展示 `secrets/DEMO_ACCOUNT_CREDENTIALS.md`。
3. 不现场修改数据库结构。
4. 不展示过长 SQL 文件全文。
5. 不把教师评价功能讲成已实现。
6. 不把后续扩展讲成已实现。
7. 不在普通用户界面展示数据库异常堆栈。
