\chapter{逻辑结构设计}

\section{从 ER 模型到关系模式}

逻辑结构设计的任务是把概念结构设计中的实体、属性和联系转换为关系数据库可以直接实现的关系模式。第 4 章以“关系模式表格 + 主外键说明 + 多对多转换说明”为核心表达方式，说明 openGauss 数据库中各表的逻辑结构。

本系统的转换原则如下：实体转换为基本关系；一对多联系通常通过在多端表中保存外键实现；多对多联系转换为独立中间关系；多值属性转换为独立关系；自关联联系通过同一实体表的两个外键表达。

\section{主键、候选键与唯一约束说明}

主键用于保证实体完整性。系统中大多数业务实体使用稳定业务编号作为主键，例如 \code{student.student_id}、\code{teacher.teacher_id} 和 \code{course.course_id}；会话、教学班、选课记录和日志等事件型数据使用 \code{BIGSERIAL} 代理主键，例如 \code{offering_id}、\code{enrollment_id} 和 \code{log_id}。这种设计兼顾了业务可读性和事件记录的自动增长需求。

候选键和唯一约束用于表达业务唯一性。\code{user_account.username} 保证登录名唯一；\code{student.user_id}、\code{teacher.user_id} 和 \code{admin_profile.user_id} 保证一个账号最多对应一种同类业务档案；\code{enrollment(student_id, offering_id)} 保证同一学生不能重复选择同一教学班；\code{course_schedule(offering_id, weekday, start_section, end_section)} 保证同一教学班不会重复登记同一时间片。

此外，\code{department.dept_name}、\code{major(dept_id, major_name)} 和 \code{classroom(building, room_no)} 等业务唯一约束进一步把现实语义固化到数据库层，有利于减少重复数据。

\section{外键与参照完整性说明}

外键用于表达关系模式之间的参照完整性。组织结构中，\code{major.dept_id} 引用 \code{department.dept_id}；人员档案中，\code{student.user_id}、\code{teacher.user_id} 和 \code{admin_profile.user_id} 引用 \code{user_account.user_id}；课程教学中，\code{course_offering} 通过 \code{course_id}、\code{semester_id}、\code{teacher_id} 和 \code{classroom_id} 分别引用课程、学期、教师和教室；选课成绩中，\code{enrollment} 引用学生和教学班，\code{score_change_log} 引用选课记录和操作账号。

这些外键保证了“不能为不存在的学生选课”“不能为不存在的教学班登记时间片”“不能记录不存在选课记录的成绩修改”“学期不能引用不存在的绩点规则”等基本规则。需要注意的是，角色类型一致性、教学班容量不超过教室容量、先修课程环路和选课时间冲突属于跨表业务规则，普通外键不能完整表达，系统已在第 6 章通过触发器进一步说明。

\section{多对多联系转换}

学生与教学班之间是典型多对多联系：一个学生可以选择多个教学班，一个教学班也可以被多个学生选择。若直接在学生表中保存课程列表，或在教学班表中保存学生列表，都会产生非原子属性并破坏第一范式。因此逻辑设计使用 \code{enrollment} 作为中间关系，把 M:N 联系转换为两个 1:N 联系：

\begin{itemize}
  \item \code{student} 与 \code{enrollment} 构成 1:N，一名学生可以对应多条选课记录；
  \item \code{course_offering} 与 \code{enrollment} 构成 1:N，一个教学班可以对应多条选课记录。
\end{itemize}

\code{enrollment} 不只是连接表，也保存联系属性。\code{select_time} 表示选课时间，\code{status} 表示选课状态，\code{final_score} 表示该学生在该教学班中的最终成绩，\code{remark} 保存备注。因此，把 \code{enrollment} 设计为独立关系既解决了多对多转换，也为退课、成绩录入和成绩审计提供了数据基础。

课程与先修课程之间也是多对多自关联。一门课程可以有多门先修课程，一门课程也可以作为多门课程的先修课。系统使用 \code{course_prerequisite(course_id, prereq_course_id)} 表达该自关联，其中两个字段都引用 \code{course.course_id}，复合主键保证同一先修关系不会重复登记。

\section{课程定义、教学班与时间片}

\code{course} 与 \code{course_offering} 的分离是逻辑设计中的关键点。\code{course} 保存课程定义，例如课程名称、课程类型、学分、总学时和所属学院；\code{course_offering} 保存某课程在某学期、由某教师、在某教室开设的具体教学班。这样，同一课程在不同学期或不同教师下开班时，不需要重复保存课程名称、学分和学时，减少了更新异常。

\code{course_schedule} 则用于表达教学班的多值时间属性。一个教学班可以有多个上课时间片，因此逻辑设计将时间片独立成表，每行保存 \code{weekday, start_section, end_section}。该设计使数据库能够直接按星期和节次进行时间冲突检查，而不是依赖应用层解析展示文本。
