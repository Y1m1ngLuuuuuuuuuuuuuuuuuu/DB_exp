# Large Demo Dataset Plan

## 1. Schema Snapshot

The demo dataset is generated for the current openGauss relational schema:

- Organization: `department`, `major`
- Authentication and profiles: `user_account`, `user_session`, `student`, `teacher`, `admin_profile`
- Teaching resources: `semester`, `course`, `classroom`, `course_offering`, `course_schedule`, `course_prerequisite`
- Enrollment and grades: `enrollment`, `score_change_log`
- GPA policy extension: `grade_policy`, `grade_scale`, `semester.grade_policy_id`

The generator does not restore removed base columns such as `course_offering.selected_count`, `course_offering.schedule_text`, or `enrollment.gpa_point`.

## 2. Trigger and Constraint Impact

The seed data must satisfy existing database-level rules:

- Profile triggers require `student`, `teacher`, and `admin_profile` rows to reference matching `user_account.role` values.
- `course_offering.max_capacity` must not exceed `classroom.capacity`.
- `course_prerequisite` cannot be self-referential and cannot form cycles.
- `enrollment` rows with `status='selected'` are guarded by `trg_enrollment_guard`, including student status, open offering, open semester, selection window, capacity, same-course cross-offering, timetable conflict, and prerequisites.
- `score_change_log` is generated by updating `enrollment.final_score` with `app.current_user_id` set in the transaction.

Historical `completed` enrollment rows are inserted as completed records. Current `selected` rows are generated only for the open semester and are planned to satisfy trigger checks.

## 3. Data Scale

Target dataset:

- 4 departments
- 10 majors
- 100 students
- 30 teachers
- 3 administrators
- 50 courses
- 4 semesters
- 20 classrooms
- About 150 course offerings
- About 200 schedule time slots
- About 900 completed enrollments
- About 400 current selected enrollments
- About 50 dropped enrollments
- About 80 score change audit logs generated through the score trigger

## 4. Naming Rules

- Students: `student_id` and login `username` use `20240001` to `20240100`.
- Teachers: `teacher_id` and login `username` use `T001` to `T030`.
- Administrators: `admin_id` and login `username` use `A001` to `A003`.
- Courses use department prefixes, for example `CS101`, `MA101`, `FL101`, and `EM101`.

## 5. Password and Credential Policy

Passwords are generated with fixed random seed `20260611` for reproducibility. Each plaintext password:

- Uses uppercase letters, lowercase letters, and digits.
- Has length 14.
- Contains at least one uppercase letter, one lowercase letter, and one digit.

The database stores only SHA-256 hexadecimal `password_hash` values. Plaintext initial passwords are written only to `secrets/DEMO_ACCOUNT_CREDENTIALS.md`, which is ignored by Git and must not be included in the LaTeX report.

## 6. Distribution Strategy

- Students, teachers, and courses are distributed across four departments.
- Majors are assigned according to department.
- Course types cover `required`, `elective`, and `public`.
- Current semester offerings are `open`; historical offerings are `closed`.
- Offering capacity is always less than or equal to classroom capacity.
- Current selected enrollments are generated with timetable and same-course checks in memory before SQL is emitted.
- Prerequisite courses are passed by students before advanced courses are selected.

## 7. Grade Strategy

Completed enrollments receive final scores with a realistic distribution:

- 90--100: about 15%
- 80--89: about 30%
- 70--79: about 30%
- 60--69: about 18%
- 0--59: about 7%

Prerequisite foundation courses are kept above 60 when they are needed to satisfy later selected or completed advanced courses.

## 9. Validation Steps

After generation and import:

1. Execute `opengauss_setup/sql/local/seed_large_demo_dataset_20260611.sql`.
2. Execute `opengauss_setup/sql/validate_large_demo_dataset.sql`.
3. Execute `opengauss_setup/sql/test_triggers_constraints.sql`.
4. Execute `scripts/concurrency_enrollment_test.py`.
5. Run `python -m compileall .`.
6. Run Streamlit smoke tests.
7. Compile the LaTeX report.
